# 产品需求文档（PRD）：学术论文社区与协作平台

- 文档版本：v0.1（评审稿）
- 状态：Draft
- 适用范围：Web 端（网页版）

---

## 1. 产品概述

### 1.1 背景

学术研究者获取前沿信息的主要渠道是**他人转发**，而非主动检索。但现有平台存在两个断裂：

- **筛选成本高**：arXiv / 期刊每日新增量大，逐篇判断与自身研究的相关性极其耗时；
- **阅读被打断**：社区里看到论文链接，需要跳转到第三方 PDF 站点，脱离讨论语境，读完难以回到讨论；
- **讨论与产出分离**：在社区读完论文后，协作写论文发生在另一套工具（飞书/Word/Overleaf）里，文献、批注、稿件无法打通。

### 1.2 产品定位

> 一个以「关注学术大V的转发」作为信息筛选机制的学术社区，并提供从共读文献到共同成稿的一体化协作空间。

核心主张：**不做个性化推荐算法**，用人的判断（大V转发、编辑精选、专题策展）替代机器排序，降低信噪比问题的同时保留社区信任。

### 1.3 目标用户

| 角色 | 描述 | 核心诉求 |
|---|---|---|
| 读者（研究生/工程师） | 跟进方向前沿，但缺乏筛选能力 | 低成本看到「值得读」的论文，快速判断是否相关 |
| 大V/领域专家 | 已有判断力和影响力 | 高效转发 + 表达观点，建立个人学术品牌 |
| 协作团队（课题组/合作作者） | 2–8 人共同完成一篇论文 | 共享文献、共同编辑、批注与版本管理 |
| 平台运营 | 冷启动与内容质量把控 | 精选策展、大V引入、违规处理 |

### 1.4 差异化价值

1. **信息流内联预览**：卡片内可直接翻阅 PDF，不点进去、不跳转，讨论与原文同屏；
2. **转发即解读**：转发强制或鼓励附加观点，形成「大V解说 + 原文」双层结构；
3. **规则透明的时间/热度排序**：用户能理解「为什么看到这条」，而非黑盒推荐；
4. **阅读到成稿的闭环**：群内文献库与论文文档共享同一套引用体系。

## 2. 术语

| 术语 | 定义 |
|---|---|
| Paper | 论文实体，承载 DOI/arXiv 等元数据，全站唯一 |
| Post | 社区动态，类型为原创或转发，可挂载 Paper 与附件 |
| 内联预览 | 在信息流卡片内直接渲染文件内容，不跳转独立页面 |
| 关注流 | 仅展示已关注用户的动态，纯时间倒序 |
| 精选流 | 由运营/大V策展的内容集合 |
| Group | 群组，协作的最小组织单位 |
| Document | 群组内的论文稿件，支持多人实时编辑 |
| Annotation | 针对文档选区或 PDF 指定页的批注 |

## 4. 核心用户旅程

### 4.1 发现与消费

```
打开首页 → 关注流（默认）→ 看到大V转发卡片
  → 卡片内直接上下滑动翻阅 PDF 前若干页
  → 判断有价值 → 点赞/收藏/评论
  → 或展开讨论区看他人观点
  → 加入稍后读
```

关键指标：**卡片内阅读时长 / 卡片展开率 / 跳转独立页比例（越低越好）**。

### 4.2 转发与表达

```
点击转发 → 选择「转发并评论」→ 输入观点 → 可 @ 群组/成员
  → 发布后出现在关注者的关注流
```

### 4.3 群组协作

```
创建群 → 邀请链接分享 → 成员入群
  → 群文件库上传/收藏论文（自动解析元数据）
  → 新建论文文档 → 多人实时编辑
  → 对段落批注讨论、@ 提及
  → 插入引用 → 生成参考文献
  → 导出 Word / PDF / LaTeX
```

### 4.4 冷启动（运营）

```
运营邀请领域大V → 大V发布首条转发 → 编辑精选位推荐
  → 新用户注册 → 默认关注 3–5 位大V → 关注流即刻有内容
```

## 5. 信息流设计规范

### 5.1 三档信息流

| 流 | 内容来源 | 排序 | 默认 |
|---|---|---|---|
| 关注流 `following` | 已关注用户的 Post | 时间倒序（发布时间） | 是（有 ≥1 关注时） |
| 全站流 `all` | 全站公开 Post | 时间倒序 | 否（无关注时默认） |
| 热门流 `hot` | 全站公开 Post | 热度分衰减排序 | 否 |

**明确不做**：基于用户画像、行为序列、协同过滤的个性化排序。所有排序规则对用户可见（页面上提供「排序规则说明」入口）。

### 5.2 热度分公式（v1）

```
raw_score = 1.0 * likes + 2.0 * comments + 3.0 * reposts
hot_score = raw_score / pow(hours_since_created + 2, 1.5)
```

调整原则：

- 转发权重最高（符合「大V策展」的产品逻辑）；
- 时间衰减半衰期约 12 小时；
- 热度只在 `hot` 流生效，关注流不做任何加权。

### 5.3 反作弊

- 同一用户对同一 Post 的同类互动只计一次；
- 注册 < 7 天或互动数 < 5 的账号，权重系数 0.3；
- 短时间窗口内同 IP/设备批量互动，进入人工复核，不计入热度；
- 举报数超过阈值的 Post 自动降权并从 `hot` 流移除。

### 5.4 卡片形态

信息流卡片统一包含：

- 作者信息、发布时间、关注按钮；
- 正文（富文本，最多折叠 6 行，可展开）；
- 若挂载论文：**内联预览区**（默认高度 480px，内部滚动翻页，底部显示页码与「在独立页打开」）；
- 若为转发：原 Post 摘要 + 原文预览；
- 互动栏：点赞、评论、转发、收藏。

内容密度要求：单屏至少 2 张卡片，预览区不得撑破卡片。

## 6. 功能需求

优先级定义：P0 = MVP 必须；P1 = 协作核心；P2 = 增长与壁垒。

### 6.1 账号与身份（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| A-01 | 邮箱注册/登录，支持验证码与密码 | 注册后 60 秒内可完成首次发帖 |
| A-02 | 第三方登录（GitHub / Google / 微信，按上线地区取舍） | 首次登录自动创建账号并引导补全资料 |
| A-03 | 个人主页：简介、机构、研究方向、发帖/转发/收藏 Tab | 支持分享链接，SSR 可被搜索引擎索引 |
| A-04 | 机构邮箱认证 | 认证后显示「认证学者」标识，可随时撤销 |
| A-05 | 大V标识（运营授予） | 运营后台可授予/收回，操作留审计日志 |

### 6.2 论文实体与元数据（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| P-01 | 粘贴 DOI / arXiv / URL 自动解析元数据 | 支持 DOI、arXiv、OpenReview、ACL Anthology；解析成功率 ≥ 90% |
| P-02 | 元数据编辑与去重合并 | 同一 DOI 全站唯一；重复创建时提示合并 |
| P-03 | 论文详情页：摘要、作者、期刊、引用数、相关讨论 | SSR 渲染，LCP < 2.5s |
| P-04 | 手动补录（无 DOI 场景） | 必填标题 + 至少一位作者 |
| P-05 | PDF 上传并关联到 Paper | 上传后进入转码队列，5 分钟内可预览 |

### 6.3 信息流与互动（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F-01 | 三档信息流切换，状态在会话内保持 | 切换响应 < 300ms，分页游标不重复不丢失 |
| F-02 | 图文 Post 发布（富文本 + 图片 + 文件） | 支持拖拽上传，单帖附件 ≤ 10 个 |
| F-03 | 转发（可附带评论） | 转发链最多展示两层，更深层折叠为「查看原帖」 |
| F-04 | 点赞、评论（支持一级回复）、收藏 | 互动后 1s 内 UI 反馈，服务端最终一致 |
| F-05 | 稍后读 / 收藏夹（可公开/私密） | 支持批量管理 |
| F-06 | 举报与屏蔽用户 | 举报后进入审核队列，屏蔽立即生效 |
| F-07 | 话题标签与话题页 | 标签可检索，话题页按时间序 |

### 6.4 内联预览（P0，核心体验）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| V-01 | PDF 卡片内预览，可上下滑动连续翻页 | 首屏可见时间 < 1.5s；翻页无白屏 |
| V-02 | 预览只渲染可视区域附近页面 | 单卡内存占用 < 80MB；滚动 60fps |
| V-03 | Word / PPT / Excel 转 PDF 后预览 | 版式无明显错位（复杂公式允许降级提示） |
| V-04 | 图片、Markdown、代码、LaTeX 预览 | 代码高亮、公式 KaTeX 渲染 |
| V-05 | 预览内文本可选中与复制 | 文本层与视觉层对齐 |
| V-06 | 未登录/无权限时显示受限提示 | 不泄露文件直链 |
| V-07 | 滚动隔离 | 卡片内滚动不带动外层信息流 |

### 6.5 群组（P0）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| G-01 | 创建群组（名称、简介、封面、加入方式） | 加入方式支持「公开」「申请审批」「仅邀请」 |
| G-02 | 邀请链接 / 邀请码，可设置有效期 | 过期链接提示并可重新生成 |
| G-03 | 成员管理：角色变更、移除、转让群主 | 操作后 3s 内成员端同步 |
| G-04 | 群内动态流（图文 + 文件） | 与信息流一致的卡片体验 |
| G-05 | 群文件库：共享文献、按标签分类 | 支持从群内 Post 一键存入文件库 |
| G-06 | 群内 @ 提及与消息通知 | 离线用户上线后可见通知 |

### 6.6 论文协同编辑（P1）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| D-01 | 创建论文文档，支持章节大纲与目录 | 支持 Markdown 快捷输入 |
| D-02 | 多人实时编辑，显示协作者光标与选区 | 3 人同时编辑冲突率 0；延迟 < 200ms（同区域） |
| D-03 | 离线编辑后自动合并 | 断网 10 分钟内编辑内容可无损合并 |
| D-04 | 版本历史与回滚 | 保留最近 50 个自动快照，可命名里程碑 |
| D-05 | 段落批注、@ 提及、解决/重开 | 正文编辑后批注锚点不漂移 |
| D-06 | 引用插入与参考文献生成 | 支持 BibTeX 导入，引用格式可切换（GB/T 7714、APA、IEEE） |
| D-07 | 导出 Word / PDF / LaTeX | 导出保留章节结构与公式 |
| D-08 | 文档级权限（可编辑/只读/指定成员） | 无权限用户只读，且不可导出 |

### 6.7 检索（P1）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| S-01 | 统一搜索：论文、帖子、用户、群组 | 输入 300ms 内出结果，首屏 10 条 |
| S-02 | 中文分词与英文词干化 | 中文标题召回率 ≥ 85%（标注集） |
| S-03 | 筛选：时间、类型、标签、作者 | 条件可组合并保留在 URL |
| S-04 | PDF 全文检索 | 命中片段高亮并定位到页 |

### 6.8 通知（P1）

- 渠道：站内通知中心 + 邮件（可配置）+ 浏览器推送（P2）；
- 事件：评论、回复、@、转发、点赞聚合、入群申请、文档被编辑；
- 支持按类型静音与免打扰时段。

### 6.9 AI 辅助（P2）

定位为**阅读辅助**，不参与信息流排序：

- 论文一句话摘要 / 贡献点提取；
- 中英对照翻译（段落级）；
- 相关论文推荐（仅在论文详情页展示，由向量相似度召回，需标注「AI 推荐」）；
- 文档写作助手（润色、术语一致性检查）。

### 6.10 明确不做（Out of Scope）

- 个性化推荐算法与用户画像建模；
- 实时音视频会议；
- 期刊投稿系统对接 / 同行评审流程；
- 移动原生 App（首期只做响应式 Web）；
- 文献爬虫抓取全文（只做元数据解析与用户上传文件）。

## 7. 非功能需求

### 7.1 性能

| 指标 | 目标 |
|---|---|
| 首页 LCP | < 2.5s（4G，P75） |
| 信息流翻页 | < 500ms |
| 内联预览首屏 | < 1.5s |
| 协同编辑同步延迟 | < 200ms（同区域） |
| 文件转码完成 | P95 < 5min（≤ 50MB PDF） |

### 7.2 可用性与容量（首年假设）

- 日活 1 万，峰值 QPS 300；
- 存储：文件总量 5TB，年均增长 3TB；
- 可用性目标 99.9%（月度）。

### 7.3 安全与合规

- 上传文件类型白名单，服务端 MIME 嗅探 + ClamAV 扫描；
- 富文本输出统一 sanitize，防 XSS；
- 对象存储私有桶 + 预签名 URL（有效期 ≤ 15min），禁止直链分享；
- 用户数据导出与注销能力；
- 内容审核：敏感词初筛 + 人工复核队列；
- 操作审计日志保留 ≥ 180 天。

### 7.4 SEO

- 论文详情页、作者主页、话题页 SSR 渲染；
- 输出结构化数据（ScholarlyArticle）；
- 生成 sitemap 与 canonical。

### 7.5 可访问性

- 键盘可完成信息流浏览与发帖；
- 预览区提供「下载/新窗口打开」作为无障碍替代路径。

## 10. 待评审确认项

1. 大V是否需要「转发权重加成」以外的特权（如置顶、专题主持）？
2. 群组是否需要「公开群」的发现入口，还是仅邀请制？
3. 论文文档的引用格式优先级，是否需要支持 LaTeX 模板（Overleaf 兼容）？
4. 文件单文件大小上限（建议 100MB）与存储配额策略（免费/付费）。
5. 是否需要机构版（实验室空间、成员统一管理）作为 P2 商业化解法。
